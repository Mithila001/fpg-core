# E03 — Room sizing research

E03A explores how room dimensions and area ratios restrict one another before a
configuration is considered for generation. Spatial floor-plan feasibility
requires separate checks for placement, geometry, access, and other constraints.

## Run an analysis

Open **E-03-A** in Lab and edit the selected room counts. **Use maximum counts**
fills the allowed counts while respecting the attached-bathroom policy.
**Validate fields** checks the draft, and **Start analysis** checks mathematical
feasibility in the workspace. Setup edits carry into the run as an unsaved draft.
Navigating away or reloading ends the run.

**Overview** groups configured and feasible ranges, option counts, and flexibility
by room type. **Room configurations** edits dimensions, aspect ratios, and counts.
Select a matrix cell in **Relationship matrix** to edit a rule. **Diagnostics**
explains conflicts and inactive rules and contains an expandable example of a
compatible sizing arrangement. The sidebar shows feasible width, length, and
same-type variation for the selected type.

Use **Area-range locks** in the sidebar to enter inclusive minimum and maximum areas
in whole project units². A lock applies to every instance of the selected type.
You can edit, remove, or combine locks across types. The exact analysis intersects
each requested range with the original achievable areas, then checks global
support. The requested bounds stay visible when only part of the range is
feasible, including gaps between achievable areas. A range excluding all
achievable areas produces a range-lock conflict. Removing locks restores options
across the relationships. A lock on a type with zero instances is inactive.

## Configuration

E03A owns [its JSON file](../../experiments/e03a/config.json). **Import from E02A**
reads the current E02A default-size room definitions, count policy, project
units, and initial solver profile's room aspect rule. Preview changed fields and
selected counts, then apply them to the draft. The imported limits adjust counts
only where needed. If a draft changes after the preview was prepared, request
a fresh preview. E03A's ratio rules stay in the draft, and normal analysis
reads only E03A data. The attached-bathroom limit applies when the imported
policy rejects counts greater than the bedroom count.

**Save configuration** atomically replaces E03A's file with the validated draft.
Mathematically incompatible drafts can be saved for research. If another tab
has saved since the current draft was loaded, export the draft or reset to read
the latest file. **Export JSON** downloads the current valid draft. **Reset
unsaved edits** reloads the saved configuration. Range locks are temporary run
state excluded from both save and export.

One metre is 10 project units. One square metre is 100 square project units.
Dimensions use integer X and Y spans. Bounds in the file can contain decimal
values, which the editor accepts as text and the exporter preserves as decimal
strings. Both spans meet the minimum width. Maximum width constrains the
shorter span for ordinary rooms and the X span for garage and veranda.
Aspect bounds use X divided by Y and the initial solver profile's integer scaling.

## Rules, exact support and diagnostics

An off-diagonal matrix cell compares each room of the row type to every room
of the reference column type. It constrains the quotient of their areas. A
diagonal rule caps the difference between two same-type rooms relative to the
smaller area. Both rule families preserve their identities for editing and
diagnostics and participate in the same solve. Rules with absent types, or fewer
than two instances of a same-type rule, are inapplicable. Hallways are excluded.

Counts select which relationships apply. Once a type participates, adding
identical instances increases the number of relationships and can increase the
number of possible arrangements. Under these rules an instance can copy the area of another
instance of its type, so adding identical instances does not itself narrow
the individual feasible range. The overview groups their shared results.

Enumerating integer dimension pairs produces a sorted domain of achievable areas
for each room. The product constraint leaves gaps in this domain. Each ratio
bound becomes a monotone lower bound on another room. The work queue starts at
the lowest domain values and raises a target to the least available value that
satisfies its bound. By induction each update remains at or below any compatible
assignment. Finite domains make the process terminate at a compatible least
assignment or prove that a domain has no value left. Fixing one candidate and
rerunning the same procedure establishes whether it has global support. A
witness takes one dimension pair associated with each assigned area.

Flexibility is the percentage of originally achievable area values that have
global support. An empty original domain has undefined flexibility. Each
supported value occurs in some compatible arrangement, so combining separately
supported choices may still create a conflict. Flexibility measures this sizing
model's restrictions. It has no calibration to architectural quality or
generation success.

Same-type variation measures how far two instances can differ in a single
compatible arrangement. A type can retain 100% of its individual options
while a zero-spread rule requires all its instances to have equal areas.
For each supported area of one instance, the analyzer fixes that area and
runs the same propagation in reverse to find the greatest jointly feasible
area of the other. It reports the maximum absolute difference and maximum
relative spread. These maxima can come from different pairs of areas.
The comparison against the same-type rule alone also accounts for discrete
dimensions and the current range lock. Fewer than two instances makes
same-type variation inapplicable.

Diagnostics show dimension failures, standalone and combined rule failures, and
lock-induced failures. A promotion chain identifies contributing rules and may
include more than the smallest conflicting set. The suggested changes require
an explicit edit. Analysis can be incomplete after a five-second solve budget,
more than 64 room instances, or over 100,000 dimension pairs for a room spec.

## Verification

From the Lab environment, run
`python -m pytest tests/test_e03a.py` and `python -m scripts.verify_fpg_core`.
Try editing setup counts, importing the current configuration, and locking the
living-room type to 1,400–1,450 units². The starter rules produce a conflict
that clears when the lock is removed. A wider range of 1,400–2,000 units²
demonstrates partial support.
