# P01 experiment family

P01 investigates candidate layouts and the floor-plan pipeline. Its variants
share configuration handling, experiment records, and the background queue.
P01 namespace seeds are `P01A`, `P01B`, and `P01C`; `COMM` identifies shared records;
they identify shared records and experiment variants, not a general plugin system.

| Variant | Distinctive execution |
| --- | --- |
| P01A | Preprocess -> candidate search -> circulation -> candidate scoring; spend a requested trial budget |
| P01B | Saved cleaned candidate -> initial solve -> repeated refinement -> post-processing -> final scoring |
| P01C | P01B iteration flow followed by openings and final scoring |

## Core hand-offs and policy

The adapter uses supported feature roots and `fpg_core.domain`. Preprocessing owns
the exact candidate grid. For each candidate, Lab passes circulation rules only
when both endpoint room types are present; required transit types still apply.
Circulation can remove/consolidate hallway hints; use the
cleaned candidate to obtain the matching generation specification. The solver must
place every supplied room. Refine existing plans, then post-process before openings
so geometry changes do not invalidate door/window placement. Final scoring differs
from candidate scoring. See the [Core pipeline](../../../docs/architecture/pipeline.md).

P01B imports a complete cleaned candidate and matching generation specification.
Trial budgets and retention are Lab experiment policy; generation rules stay in Core. The saved
Lab profile translates to typed Core configuration and is checked against public
Core validation. Keep room relations and opening policies consistent. Circulation
route rules and candidate relationship scoring rules are configured separately.
Required transit types are supported for circulation rules; relationship scoring
does not support them.

## Recording and lifecycle

Runs preserve request/configuration snapshots, hashes, Core version, stages,
statuses, timing and errors. Later profile edits do not alter past runs. P01A omits
individual trial records when debug storage is disabled.

P01B and P01C run independent iterations. P01C generates openings after post-processing
and scores the resulting plan. A failed stage stops only that iteration. The P01C
run page can copy the completed plan with openings even if scoring fails. Paste it
into [E01A](e01.md) for session-only traffic analysis.

## P01B presets and inspection

Copy a P01A trial's cleaned hint map with the copy icon in replay or on its trial
page. New P01A debug trials contain the matching generation specification; older
trials can reconstruct it when their prepared input and cleaned candidate were saved.
Paste the JSON into P01B, inspect the preview,
and save it as a named preset. Preset deletion does not affect prior runs.

Choose a preset, system configuration, initial solver time limit, 0–5 refinement
rounds, and 1–100 iterations. Disabling hints removes the coordinates from initial
solving while preserving the specification. Each iteration starts independently;
the same solver seeds and settings are used throughout the experiment. Parallel
solver execution and time limits may still produce different outputs.

The optional `experiments.p01b_refinement` system configuration entry accepts the
same solver-stage JSON shape as `floor_plan_solver.refinement_a`; when omitted,
Core's default first refinement profile is used. Each round uses that same profile
and receives the preceding plan. P01B forces the existing-plan seed source. It does
not run Candidate Circulation or opening generation. Geometry snapshots are always
retained. Select a stage and iteration on the run page; the original hints can be
overlaid only when hints were enabled. Scoring and stage errors are saved separately.
The selected stage is retained when switching iterations; if that stage is unavailable,
the initial snapshot is shown until the selected stage is available again.

Termination is cooperative between stages; active Core work returns before it can
stop. Startup recovery marks abandoned active runs interrupted. Use a single Lab
process per database and isolated databases for headless checks beside the UI.

## P01A visual replay

After a run completes, fails, is terminated, or is interrupted, its run page offers
hint-map replay when candidate geometry was saved. Enable **Store debug data**
before submitting the run; missing geometry cannot be recovered from scores.
Start with 100 trials and use 500 for longer observation. The saved configuration
is a reproducible baseline, not an established optimal configuration.

Replay defaults to the Hints view, all trials, raw hints, two frames per second, and four fading
onion skins. Play/pause, previous/next, restart, a frame slider, and 1/2/5/10 fps
controls operate on cached saved trials. Playback stops at the last frame.
**Improvements only** keeps strictly increasing scores, preserving the first winner
on ties. **Jump to best** selects the run's recorded winner. Failed and missing-score
trials remain in chronological playback; unavailable geometry is explicitly empty.

Enable **Cleaned hints** to inspect the circulation output actually evaluated
by candidate scoring. Room colors and compact labels retain identity throughout
the run; hover shows full names, IDs, and coordinates. Missing hallway points are
omitted. Geometry keeps the prepared floor boundary, exact grid, equal axes, and
zoom while frames change. Only the prepared grid is drawn; automatic axis grid
lines are disabled. A responsive checkbox grid selects any subset of the run's
prepared/recorded room identities, including hallways, and defaults to all rooms.
**Select one** keeps only the first checked room when enabled; checking a different
room then unchecks the others. Turning it off allows multiple selections without
changing the checked room. **Select all / Deselect all** selects the complete set
or clears it; selecting all turns off **Select one**. The selection grid sits next
to the compact playback/settings controls above the canvas on wide screens.
Room controls are inside a collapsed **Rooms** panel with a selected count.
An empty selection
shows only the grid and floor boundary. **Previous frames** changes the trail depth
from zero (off) to the number of preceding frames available in the run, defaulting
to four or fewer for short runs. Trails fade across the chosen window and count
displayed frames in improvements mode; no movement is interpolated between proposals.

In the **Heatmap** view, with exactly one room selected, **Show placement heatmap** pauses playback and
switches the canvas to an accumulating placement-frequency view. Resume playback
to grow it, or scrub backward to remove later observations. Counts include all
trials through the current trial number, even in improvements mode, and follow
the raw/cleaned geometry selection. Missing geometry or an absent room contributes
nothing; failed trials with recorded geometry still contribute. The button is
disabled if the selected room/source has no observations anywhere in the run.

Heatmap cells use the exact candidate nodes, clipped to the floor boundary, with
no smoothing. A continuous blue-to-red gradient shows zero/low counts through the
busiest location so far; the count colorbar rescales as the peak grows. Hover shows
the grid coordinate, count, and share of observed placements. Before the first
observation, the canvas reports no placements. The current room marker remains
visible; trails are hidden until **Show motion** restores their configured depth.
Selecting zero/multiple rooms, or a source without observations, exits heatmap mode.

The **Circulation** view uses the same canvas, trial slider, and playback. It starts
after cleanup with all paths selected. **Before cleanup** shows the final original
routing pass against raw hints. Path selections persist across trials by rule and
endpoint identities; a path absent from a trial is not drawn. Select/deselect all
applies across the saved run. Solid blue paths are public; dashed amber paths are
private. Each path shows its efficiency score, with steps, turns, reference cost,
and movement/perimeter/turn/conflict costs in expandable details. These diagnostics
are separate from the candidate's overall score. Hallway labels show traffic roles;
crosses mark removed hints and hover reports unused/consolidated removal reasons.

Core does not currently return the final paths after consolidation. For new P01A
debug trials, Lab records `circulation_data.lab_final_routing`: a diagnostic reroute
through the cleaned candidate using the public circulation API with consolidation
disabled. Its `paths`, `hallway_traffic`, and `efficiency_score` come from that execution,
not a captured internal consolidation pass. This extra debug-only work does not
replace candidate scoring or change its input. Failure to capture diagnostics is
saved as an `error` in this object and does not reject a valid candidate. Original
Core circulation details remain intact. No database migration is needed.

New P01A debug trials also record `circulation_data.lab_generation_specification`
for the cleaned candidate, preserving its selected hallway identities. If this
snapshot cannot be constructed, `lab_generation_specification_error` records the
failure without rejecting the trial. Older trials do not have this snapshot.

Older snapshots without these diagnostics show after-cleanup paths as unavailable;
**Before cleanup** can still use their original saved passes. Rejected trials show
raw hints and their error when no circulation result exists. Switching views pauses
playback and turns the heatmap off; room/path selections and zoom are retained.

The selected frame shows its score, status, best-so-far score, and change from the
previous scored trial, plus evaluator raw scores/contributions and saved errors.
Each evaluator has a progression chart over the complete run with raw 0–100 scores
and its own running maximum, plus status/contribution in hover. Unavailable or
unevaluated raw scores remain gaps. An evaluator's best may come from a different
trial than the best total score. The score-chart playheads follow the frame.
Clicking a P01A trial ID in the history pauses and seeks the shared replay, switches
to all trials if needed, and scrolls it into view. Room/source selections, trail
depth and heatmap mode are retained. Dedicated trial URLs remain usable; history
uses those links when replay is unavailable.

Successive candidates are proposals,
not a continuous room-motion simulation. Higher candidate scores and plausible
hint positions do not establish better final floor plans; that requires a separate
downstream comparison. Replay does not tune configuration or rerun Core stages.

## Changes and verification

Inspect `flows/p01.py`, the relevant service, adapter/codec, runtime registration,
and UI/runner dispatch according to the change. Reuse P01 for different profiles;
create another family when execution behavior is materially different. Update this
file when variants, stage hand-offs, retention, or failure behavior change.

Start with `python -m scripts.verify_fpg_core`. Existing `tests/test_lab.py` checks
P01A debug modes, iteration failures, snapshots, shutdown and
recovery using real preprocessing/search and deterministic expensive-stage results.
For real checks use the [bounded headless commands](../../README.md#headless-experiments).
Do not require complete research runs for every Core or Lab change.
